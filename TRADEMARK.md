# Trademark Policy

This policy explains how the official Buildchain project names and marks may be
used. It is about project identity, not the copyright license for this
repository.

## Project Marks

Buildchain project marks include names, logos, domain names, release names,
package names, workflow names, and other identifiers associated with the
official project, including:

- Buildchain
- Buildchain Release Passport
- Kungfu Buildchain
- package or product names that use the Buildchain or Kungfu brand

The Apache-2.0 license for this repository grants copyright and patent
permissions. It does not grant trademark rights or permission to imply that an
unofficial product, fork, service, release, package, or organization is the
official Buildchain project.

## Allowed Uses

You may use the Buildchain name to make truthful, non-confusing references,
such as:

- describing that your repository uses Buildchain;
- linking to the official Buildchain repository or release;
- discussing Buildchain in documentation, issues, articles, benchmarks, or
  talks;
- identifying an unmodified official release by its original name.

Use the marks in a way that makes clear who is responsible for your software,
service, workflow, release, or content.

## Uses That Need Permission

Please get written permission before using Buildchain marks in ways that may
imply official status, sponsorship, endorsement, or control, including:

- naming a fork, hosted service, commercial product, package, app, or workflow
  collection as if it were the official Buildchain project;
- using Buildchain logos or visual identity as the primary branding for an
  unofficial product or service;
- registering domains, social accounts, package names, organization names, or
  workflow marketplaces that are confusingly similar to official Buildchain
  marks;
- distributing modified release tooling, release passports, or action bundles
  in a way that makes them look like official builds.

## Forks And Modified Builds

Forks and modified builds should use names that are clearly distinct from the
official project. A reasonable pattern is:

```text
<Your Product>, powered by Buildchain
<Your Fork>, based on Buildchain
```

Do not use a name, logo, release channel, package namespace, signing identity,
GitHub organization, release page, or action reference that makes users believe
your fork is produced or endorsed by the official Buildchain maintainers.

## Official Channels

Official channels may include:

- the `kungfu-systems` GitHub organization;
- official package scopes and registries used by the maintainers;
- official release pages, tags, release passports, and artifact bundles;
- official Buildchain documentation and sites.

If a channel is not controlled by the official maintainers, it should not claim
or imply that it is official.

## Reporting Confusing Use

If you see confusing or misleading use of Buildchain marks, open an issue or
contact the maintainers through the official project channels.
Security-sensitive cases should use the private vulnerability reporting path in
`SECURITY.md`.
